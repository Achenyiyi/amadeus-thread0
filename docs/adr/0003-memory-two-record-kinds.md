# 记忆分两类记录，由回复后评估维护

第一版的记忆由历史和两类长期记录组成。历史按顺序存下每一句话和它的时间，提示词里只放最近的一段；更早的内容只能通过长期记录进提示词，不做对话摘要。长期记录分两类：关于你的事，在你改口或纠正时整条替换；发生过的事不改写，只会被结束。两类都由回复后评估写入，替换和结束也由评估按编号指定，代码只做校验，不判断意思。她自己即兴说的话不记，她答应你的事除外。旧记忆分成十几个 namespace，同一句话会写进三处，20 条张力没有一条关闭过。现在按更新方式分成这两类，每件事只记在一处。

做法：

- **关于你的事**：你改口之前一直成立的事，一条一句，只留当前版本。称呼是其中特殊的一条，任何时候最多一条。它们每轮常驻在提示词里，超出字数上限的部分靠想起。
- **发生过的事**：每条带日期，你们之间的事和你告诉她的你自己的事都算。还没结束的叫悬着的事，分约定、没说开的事、等下文的事三种。最新的几件每轮常驻在提示词里，不靠想起：你只说一句「我回来了」，按内容想不起你上次说要去的面试。要结束一件悬着的事，就写一条新的发生过的事来结束它，这样和好本身也留在记忆里。
- **不做摘要**：滚动摘要要么每轮多调一次模型，打破每轮两次调用的约定；要么让评估每轮改写一段摘要，错误会一轮轮累积，也很难测。值得记的，评估已经写成了长期记录。
- **她自己说的不记**：人格设定是她身份的唯一出处（ADR-0001）。她即兴说的喜好和看法要是记下来、下一轮再放进提示词，人格就会被一点点改掉。她自己的变化属于自主里的成长。代价是她的说法可能前后不一，要靠人格设定把她稳定的喜好和习惯写够来压住。
- **按编号维护**：已有记录交给评估时都带临时编号，评估在输出里写明替换第几条、结束哪几条、收回哪几条。编号不合法的条目整条丢掉，不退化成新增。两条记录是不是同一件事、有没有矛盾，代码不管。
- **不做物理删除**：替换、结束、收回都只改状态。

## 否决的做法

- **只分一类**：每条都是一句话加日期。这样分不清哪些该常驻、哪些该替换。
- **照旧系统细分**（profile、likes/dislikes、timeline、repair、tension……）：同一件事分别写进几处，各自去重，存档里 conflict_repair 每条都写了两次。
- **评估只列候选，由代码按相似度决定新增还是更新**（Mem0 的做法）：「喜欢喝咖啡」和「不喝咖啡」很相似，却应该替换；交给第二次模型调用去判断，又会打破每轮两次的约定。
- **评估每轮输出完整清单，整份覆盖**：输出越来越长，容易被截断，而且每重写一次都可能丢一条。
- **尽量多记**：旧系统平均你每发一条消息，就多出 5.3 条记录，大多是原话照抄。
